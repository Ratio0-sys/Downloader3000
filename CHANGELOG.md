# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
нумерация версий — по [семантическому версионированию](https://semver.org/lang/ru/).

## [2.1.2] — 2026-08-28

### Добавлено

- **ffmpeg и движок JavaScript теперь вшиты и в Android.** Раньше на телефоне
  не работали склейка видео со звуком и конвертация в MP3, а YouTube отдавал
  неполный список форматов. Теперь статус на Android зелёный, как на десктопе.

  Что для этого понадобилось. Статические сборки ffmpeg и QuickJS для Linux
  работают и на Android: они не зависят от системной libc. Это проверено
  запуском на устройстве под Android 15, прежде чем что-либо менять в коде.

  Сложность была в упаковке. С Android 10 приложению запрещено запускать
  файлы из своей папки данных, а единственное разрешённое место — каталог
  нативных библиотек APK. Своей опции для них у сборщика нет, поэтому
  бинарники кладутся в сгенерированный проект между двумя проходами сборки
  под именами `libffmpeg.so` и `libqjs.so`.

  Отдельно потребовалась настройка `legacy_packaging`: по умолчанию Android
  не извлекает нативные библиотеки на диск, а читает прямо из APK. Для
  настоящих библиотек это быстрее, но запустить то, чего нет на диске,
  нельзя. Любопытный побочный эффект — APK при этом стал меньше на 52 МБ,
  потому что библиотеки в архиве сжимаются.

  Приложение находит каталог нативных библиотек через `/proc/self/maps`:
  путь к нему содержит две случайные строки, которые меняются при каждой
  переустановке, и угадать его невозможно.

- **Обход блокировки по имени сайта.** У части операторов скачивание падало
  ещё до начала: `youtube.com` не разрешался в адрес, хотя сам сайт в браузере
  открывался. Проверка на живом телефоне показала, что режется только
  разрешение имён — `github.com` и `google.com` отвечали нормально,
  а TCP до серверов YouTube устанавливался без проблем.

  Теперь программа делает то же, что давно делают браузеры: если система
  ответила «нет такого имени», адрес спрашивается у публичного сервера
  по HTTPS (Cloudflare, при неудаче Google). Оператор видит только
  соединение с этим сервером и не может понять, о каком имени речь.

  Пока обычное разрешение имён работает, код не вмешивается вовсе.
  Переключатель — в настройках, по умолчанию включён. Выключать его нужно
  в сетях, где внутренние адреса знает только местный сервер имён.
  Способ не помогает, если оператор режет сами соединения, — тогда
  нужен VPN, и об этом будет видно по логу.

- `tools/fetch_android_natives.py` и `tools/inject_android_natives.py` —
  загрузка бинарников и вкладывание их в проект сборки.

### Изменено

- Сборка Android в GitHub Actions стала двухпроходной.
- Идентификатор пакета: `com.randinlonescu.downloader3000`.

### Известно

- Сборка под x86_64 идёт без вшитых бинарников: они нужны только реальным
  телефонам, а те почти всегда arm64. В эмуляторе склейка и MP3 не работают.

## [2.1.1] — 2026-08-27

Исправления по итогам проверки на живом устройстве: Infinix X6725D,
Android 15, подключён по отладке.

### Исправлено

- **Приложение падало при запуске на Android.** На экране появлялся
  трейсбек `PermissionError: '/data/Downloader3000'`. Причин было две.
  `Path.home()` на Android указывает на `/data`, куда писать нельзя вовсе,
  и именно туда вёл запасной вариант выбора папки для настроек.
  А сама функция выбора не перехватывала ошибку на последнем шаге,
  поэтому исключение улетало наружу вместо мягкой деградации.
  Теперь используется приватная папка приложения, которую сообщает Flet,
  а функция обязана вернуть путь и не бросать исключений.
- **Скачанное уезжало туда, где его не найти.** Проверка доступности папки
  создавала пробный файл `.d3000_write_test` — скрытый, без расширения.
  Общее хранилище Android такие файлы не принимает, хотя обычные `.mp4`
  и `.mp3` принимает спокойно. В итоге проверка браковала папку
  `Download/Downloader3000`, в которую приложение отлично пишет.
  Теперь пробуем тем же типом файла, какой и будем писать.
- **Шапка налезала на строку состояния.** Бейдж и кнопки перекрывали часы
  и индикатор батареи. Добавлена безопасная зона.
- **Подпись автора обрезалась** в футере на узком экране — теперь переносится
  на вторую строку.
- Подсказка под полем ссылки больше не советует нажать Enter на телефоне.

### Известно

- На Android недоступны ffmpeg и движок JavaScript, поэтому статус там
  жёлтый и показывает два замечания. Вшить QuickJS в APK не выходит:
  он собирается под платформу сборщика, а Android нужен отдельный бинарник.
  Приложение чужой файл не запускает и честно сообщает об ограничении.

### Изменено

- Windows собирается через `flet pack` на PyInstaller. `flet build windows`
  требует Visual Studio с компонентом C++ и падал в обоих окружениях,
  где его пробовали. Результат — один самодостаточный `.exe`.
- В сборку через GitHub Actions добавлен шаг загрузки QuickJS: без него
  релизные сборки уходили бы без движка JavaScript.
- Скрипты сборки перенастраивают вывод на UTF-8: кириллица в сообщениях
  роняла их на Windows-раннере с `UnicodeEncodeError`.

## [2.1.0] — 2026-08-26

### Добавлено

- **Выбор видео из плейлиста.** Ссылка на плейлист теперь сканируется,
  список показывается галочками — можно отметить только нужное.
  Кнопка «Выделить всё / Снять всё», счётчик выбранного и суммарная длительность.
- **Два языка интерфейса:** русский и английский. Определяется по системе
  при первом запуске, переключается в настройках без перезапуска.
- **Три оформления:** «Оригинал» с градиентом и стеклом, плоская «Тёмная»
  и плоская «Светлая». Акцентная гамма во всех одна.
- **Масштаб интерфейса** от 80 % до 150 % с шагом 10 %.
- **Кнопка состояния** в углу: зелёная, когда всё найдено, жёлтая при нехватке
  ffmpeg или JS-движка. По нажатию разворачивает подробности и лог.
- **QuickJS вшит в сборки.** YouTube требует решать JS-challenge, иначе отдаёт
  неполный список форматов. Раньше для этого нужно было ставить Node или Deno,
  теперь движок весом два мегабайта едет внутри программы. Если в системе
  есть Node или Deno — берутся они, потому что работают быстрее.
- Сборка Windows через `flet pack` на PyInstaller: не требует Visual Studio
  с компонентом C++, поэтому получить exe можно на любой машине с Python.
- Конфигурации запуска для VS Code, включая горячую перезагрузку.
- Сборка всех платформ через GitHub Actions.

### Исправлено

- **YouTube отдавал «This video is not available».** Ему требуется решать
  JS-challenge, а решатель подгружается yt-dlp по требованию и по умолчанию
  это запрещено. Включён официальный компонент `ejs:github`.
- Полоса прокрутки перекрывала содержимое окна.
- Строка со ссылками закрывалась серым прямоугольником: `wrap=True`
  и `expand=True` в одной строке несовместимы.
- Кнопки «Вставить» и «Сменить» молча не работали — их асинхронные
  обработчики вызывались как обычные функции.
- Светлое оформление рисовало нечитаемый жёлтый текст на белом:
  цвет был захвачен в значении аргумента по умолчанию.
- Названия режимов показывались как `mode.1080p.name` — ключи локализации
  не совпадали со значениями перечисления.

### Изменено

- Папка `sourse/` переименована в `src/`, лендинг переехал в `docs/`.
- Переключатель «скачивать плейлист целиком» убран из настроек —
  теперь это решают галочки.

## [2.0.0] — 2026-08-26

Полная переработка. Четыре `.bat`-файла заменены одним приложением
на Python и Flet, работающим на Windows, Linux, macOS и Android.

### Добавлено

- Графический интерфейс в стиле лендинга проекта.
- Четыре режима: максимальное качество, 1080p, 720p и MP3.
- Прогресс со скоростью и оставшимся временем, отмена скачивания.
- Живой лог с раскраской по важности.
- Проверка окружения при запуске: ffmpeg, JS-движок, платформа.
- ffmpeg входит в настольные сборки — ставить вручную больше не нужно.

### Исправлено

Одиннадцать ошибок исходных `.bat`-файлов:

| № | Что было |
| --- | --- |
| 1 | Путь сохранения захардкожен как `D:\download video\...` — у всех, кроме автора, программа падала |
| 2 | `yt-dlp` вызывался из `PATH`, хотя лежал рядом с батником |
| 3 | Жёстко указан `--js-runtimes deno` при отсутствии deno — терялась часть форматов |
| 4 | Наличие ffmpeg не проверялось, ошибка всплывала после скачивания |
| 5 | `yt-dlp -U` запускался на каждой итерации цикла |
| 6 | `%url%` вместо `!url!` — ссылка с символом `&` рвала команду |
| 7 | Ссылка с `&list=` утаскивала весь плейлист целиком |
| 8 | Папку сохранения требовалось создать заранее вручную |
| 9 | `exit` закрывал родительское окно консоли |
| 10 | Длинные названия упирались в предел длины пути Windows |
| 11 | Эмодзи в сообщениях не отображались в консоли |

### Удалено

- Поддержка Windows 7 и 8.1. Причина не в приложении: современный yt-dlp
  требует Python 3.10+, который на этих системах не устанавливается.
  Минимальная планка — Windows 10.
